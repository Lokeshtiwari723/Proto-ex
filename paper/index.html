Which Observable Search and Content Signals Can Help Us Rank Pages That Should Be Reviewed First?

A decision-support analysis using February 2026 page-level signals and a March 2026 proxy outcome.

Author: Lokesh Tiwari · Machine Learning Capstone

1. Abstract

This study asks which observable search and content signals can help rank pages that should be reviewed first. I used February 2026 page-level signals and a March 2026 CTR-based proxy label to compare a transparent Week-4 action-score baseline with Logistic Regression. Validation used a client-grouped 80/20 holdout with zero client overlap between training and test data. On the measured test split, Logistic Regression achieved Precision@50 of 1.00 compared with 0.76 for the Week-4 baseline. The result supports using the model as a review-prioritization aid, but it does not establish causation or guarantee future performance.

2. Introduction / Problem Statement

Content and SEO reviewers may need to decide which pages to inspect first when many pages have observable search and content signals.

A simple rule can provide a transparent starting point, but a useful ranking approach should be tested against an explicit outcome and evaluated under an honest validation design.

The goal of this project is therefore not to make a final judgment about whether a page is failing. The goal is to create a ranked review queue that helps a human reviewer decide where to look first.

Research question

Which observable search and content signals can help us rank pages that should be reviewed first?

The supported decision is review prioritization based on observable search and content signals.

3. Data

The analysis uses the FlyRank ML Internship warehouse data for a February 2026 feature window and a March 2026 label window.

One row represents one page-level search/content record identified by a client-content pair.

Feature window

  • February 2026
  • GSC impressions
  • GSC clicks
  • GSC average position
  • Word count
  • Content age in days

Label window

The March outcome is a proxy label based on whether a page's March CTR was above the median March CTR cutoff.

Pages without sufficient March impressions for the label calculation were excluded from the label calculation.

Exclusions

  • Future March outcome fields were not used as model features.
  • Label-derived fields were not used as model features.
  • Client and content identifiers were used for grouping and joining, not prediction.
  • The analysis does not use private queries, client names, or page URLs.
Data interpretation: The March CTR label is a proxy outcome, not a direct measure of business success.

4. Methodology

The first model is Logistic Regression because it is simple, interpretable, and suitable for checking whether the selected observable signals contain useful information for ranking review priority.

Model features

  • GSC impressions
  • GSC clicks
  • GSC average position
  • Word count
  • Content age in days

Baseline

The Week-4 baseline is a transparent action score based on visibility and content age. It provides a simple human-readable comparison point for the model.

Validation design

The model and baseline were evaluated using Precision@50 on the same held-out test set. Validation used a client-grouped 80/20 split so that clients did not overlap between training and test data.

5. Results

On the held-out client-grouped test set, the Logistic Regression model measured Precision@50 of 1.00, while the Week-4 action-score baseline measured Precision@50 of 0.76.

50 / 50

All 50 pages selected in the model's top-50 queue were positive under the March proxy label in this test split.

The result is evidence of useful ranking signal in this test setup. It should not be interpreted as a guarantee of future performance or as evidence of causation.

The model was also selective: many positive pages remained outside the top 50. Therefore, the queue should be treated as a prioritization tool rather than a complete list of pages needing attention.

6. Limitations & Honest Framing

  1. The March outcome is a proxy label based on March CTR relative to the median cutoff. It is not a direct measure of business success.
  2. Precision@50 was measured on one held-out client-grouped test split. The result should not be treated as a guarantee for future data.
  3. The model is designed to prioritize a small review queue. Many positive pages remained outside the top 50.
  4. The observable signals describe page performance and content characteristics. They do not establish that changing a feature will cause the outcome to change.
  5. GSC availability is not uniform across all records, so the analysis represents the available observable data rather than every possible page record.
  6. Human review is required before taking a content action. The ranking is decision-support, not an automated final decision.
Claim boundary: The measured result supports a decision-support interpretation of the ranking experiment. It does not support a causal claim or a guarantee that the model will perform the same way on future data.

7. Ranked Recommendations

The model output is used as a review-prioritization queue.

1. Review for refresh

Pages with high model priority and strong baseline visibility should be reviewed first for possible content refresh.

The reviewer should inspect the page, search intent, current content quality, and recent performance before making a change.

2. Review opportunity

Pages with high model priority but a different baseline action should be reviewed as potential search-performance opportunities.

The model score alone should not determine the action.

3. General review

Lower-priority pages can remain in the queue for later review when review capacity is available.

Human decision rule

The model ranks pages; a human decides whether an actual content change is appropriate.
